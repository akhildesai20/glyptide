# AGENTS.md — Glyptide

## Purpose

Glyptide is a lightweight, model-independent text-motion library for generative UIs: streaming responses, insertions, rewrites, continuations, and structured output. It is a **presentation layer** — it does not call AI providers and needs no API keys.

## Architecture

| Path | Role |
|------|------|
| `packages/glyptide` | Core engine, registry, appearance, stream helpers |
| `packages/glyptide-react` | Thin React wrapper |
| `site/` | Playground + AI-facing static assets under `site/public/` |
| `skills/glyptide/` | Portable Agent Skill (Agent Skills spec) |
| `prototype/` | Historical v5 study — not the production source of truth |

**Source of truth for patterns:** `packages/glyptide/src/data/patterns.json` (+ `cases.json`). Derived assets (registry JSON, llms files, pattern docs) are generated by `npm run generate:ai-docs` after `build:lib`.

Separate concerns: **Pattern** · **Motion** · **Appearance** · **Lifecycle**. Aesthetic config must never change a transient pattern’s final inherited styles.

## Commands

```bash
npm install
npm run build:lib          # build packages
npm run generate:ai-docs   # refresh llms.txt, registry, schemas, public docs
npm run build              # lib + site
npm run dev                # build lib then Vite playground
npm test                   # Vitest (site)
npm run test:e2e           # Playwright (Chromium)
npm run typecheck
npm run size
```

## Coding conventions

- TypeScript, no new core runtime dependencies without strong justification.
- Prefer native CSS, Web Animations, `requestAnimationFrame`.
- Keep semantic revision tokens (`--added`, `--removed`) independent of aesthetic presets.
- Render model text as text nodes — never inject unsanitized HTML or `eval` model output.
- Preserve existing pattern **ids**; do not duplicate patterns that differ only by color.

## Public API conventions

- Prefer `createGlyptide({ pattern: "<id>" })` over hand-rolled animation.
- Real streams: `append` / `finish` or `pipeTextToGlyptide` with `mode: "delta" | "snapshot"`.
- Use `recommendPatterns({ useCase })` for deterministic suggestions (no LLM).
- Validate configs against `site/public/schemas/*.json` when generating integration code.

## Motion & appearance rules

- Honor `prefers-reduced-motion`.
- Transient treatments must clear to **inherited** host styles (not hardcoded black/white).
- Review-bound patterns keep chrome until Accept/Discard — no fixed timeout dismissal.
- `persistGradient` is showcase-only (hero), not a product default.

## Accessibility & themes

- Announce completion/review, not every token.
- Support `theme: "light" | "dark" | "system" | "inherit"`.
- Preserve independent light/dark custom palettes.

## Performance

- Keep the core package tiny; optional examples/skills must not become mandatory deps.
- Pause/stop off-screen demos; cancel timers/animations on `destroy` / `stop`.

## Contribution & release restrictions

- Do **not** publish to npm or change GitHub visibility without explicit human authorization.
- Do **not** invent APIs, install targets, or capabilities that are not in the built package.
- After pattern/registry changes: `build:lib` → `generate:ai-docs` → tests.
- Prefer updating generated docs via the script over hand-editing `site/public/llms*.txt` or `registry/patterns.json`.
